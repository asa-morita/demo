# 体育祭 2026｜リアルタイム・トーナメント管理サイト

札幌学院大学の学サポUIを参考にした、**8チーム・複数競技**の体育祭閲覧サイトです。Cloudflare WorkersとGoogleスプレッドシートで動作します。

## 画面

下部ナビゲーションは次の順番です。

1. **スケジュール**（最初の画面）
2. **速報**
3. **対戦表**
4. **総合順位**
5. **全結果**

学サポと同じ方向性の黒いヘッダー、黄色のアクセント、丸い切り替えボタン、固定フッターを使用しています。スマートフォンはラウンド切り替え、PCはトーナメント全体表示です。

## 開催時間・種目

- **体育祭全体：12:30〜18:00**
- フットサル、バレーボール、バスケットボール、ドッチボール、綱引き、借人競争

**各競技の個別の開始・終了時刻はまだ指定されていません。** 初期表示では「時刻未定」とし、シートの `start_time`/`end_time` が入力された競技だけ具体的な時刻を表示します。表示順も仮設定であり、`order` 列から調整できます。会場 `venue` も任意入力できます。開催日自体はまだ指定されていないため掲載していません。

現段階では**6競技とも8チームの勝ち抜き型トーナメント**を仮に適用しています。借人競争・綱引き等がトーナメント形式でない場合は、競技形式に応じた順位入力方法を別途追加してください。

## 総合順位ルール（固定）

| 順位 | 獲得ポイント |
|---|---:|
| 1位 | **30点** |
| 2位 | **20点** |
| 3位 | **10点** |
| 4位以下 | **0点** |

- 1位〜3位の入賞チームのみ加点します。
- 3位決定戦がない場合、準決勝で負けた2チームを**同率3位**とし、**双方に10点**を与えます。
- 3位決定戦がある場合、勝者に10点、4位に0点。
- 3位決定戦の有無が**未定**の競技は総合順位への反映を保留します。
- 競技全体が確定した段階でその競技のポイントを一度に反映します。
- 総合順位の同点タイブレークは優勝回数、準優勝回数、3位回数。それらも同数なら同順位。
- ポイントは**コード側で30・20・10に固定**しています。旧「配点」シートは参照しません（CSVテンプレートはルールの説明用に残しています）。

## 試合結果の運用

**試合中の得点は不要です。公開画面の対戦表・速報・全結果から、試合単位の点数表示を削除しました。**

運営はスプレッドシートの**試合状態（未開始・試合中・終了）と勝者ID**だけを更新すれば次の対戦カードまで自動更新できます。得点列 `score_a` / `score_b` は互換性のため残っていますが、入力は不要です。旧形式で値が入っていた場合の勝敗自動判定だけ維持しています。**勝者IDの記録を推奨します。**

## Googleスプレッドシート（1ファイル、3タブ）

テンプレートは `templates/` フォルダにあります。

### 1. チーム

| id | name |
|---|---|
| A | Aチーム |
| ... | ... |
| H | Hチーム |

8件ちょうど。IDは競技をまたいで共通です。

### 2. 競技

| 列 | フィールド | 意味 |
|---|---|---|
| A | id | 競技識別子 |
| B | name | 表示する競技名 |
| C | third_place | あり／なし／未定 |
| D | order | 並び順（仮設定） |
| E | start_time | 例：13:00。未確定なら空欄 |
| F | end_time | 例：13:45。未確定なら空欄 |
| G | venue | 競技会場（任意） |

データ更新の際に `競技!A2:G` を読み込みます。開始・終了時刻は `HH:MM` の24時間表記で入力してください。12:30〜18:00の開催枠内で、運営が時間を割り振ることを想定しています。

### 3. 試合

| 列 | フィールド | 内容 |
|---|---|---|
| A | sport_id | 競技ID |
| B | match_id | QF1〜QF4、SF1〜SF2、FINAL、THIRD |
| C | team_a | A側のチームID |
| D | team_b | B側のチームID |
| E | score_a | 任意・表示しない（互換用） |
| F | score_b | 任意・表示しない（互換用） |
| G | status | 未開始 / 試合中 / 終了 |
| H | winner_id | **終了した試合の勝者ID** |
| I | court | 任意 |
| J | scheduled_at | 任意 |

準決勝以降の対戦相手は、それ以前の試合で入力された勝者から自動計算します。以前に確定した勝者を変更した場合、後続試合と記録が食い違えば「要確認」を表示し、不整合のある勝敗は総合ポイントに反映しません。

`THIRD` は3位決定戦が実施される場合のみ表示されます。

## Cloudflareへの公開

Gakusapoと同様、**Cloudflare Workers Static Assets** を使用します。

1. Cloudflareの Workers & Pages でGitHub `asa-morita/demo` を接続。
2. デプロイコマンドは `npx wrangler deploy`。ビルドコマンドは `npm test` を推奨。
3. Google未接続の状態では、**仮データである旨を明示したデモ**が動作します。
4. 本番運用では、Workerの環境変数に以下を設定してください。

| 変数 | 内容 |
|---|---|
| `SHEETS_SPREADSHEET_ID` | GoogleスプレッドシートのID |
| `SHEETS_CLIENT_EMAIL` | サービスアカウントのメール |
| `SHEETS_PRIVATE_KEY` | 秘密鍵。**Cloudflare Secrets**へ保存 |
| `SHEETS_API_KEY` | 代替・公開閲覧可能シートのみ（任意） |

Google CloudでSheets APIを有効にし、サービスアカウントをシートに閲覧者として共有してください。秘密鍵をGitHubに保存しないでください。

サイトは約5秒ごとにCloudflareのAPIへアクセスします。WorkerはGoogle Sheets APIの `values.batchGet` で**3タブを1リクエストで取得**し、5秒キャッシュを使用します。Cloudflareキャッシュはデータセンターごとであり、全世界で完全に一括取得する保証はありません。参加者が多い場合はCloudflare Workersのアクセス回数・料金上限に注意してください。

## 検証

```bash
npm install
npm test
npm run deploy:check
npm run dev
```

`http://localhost:8787/` でデモを確認できます。

**注意**：初期データの競技結果、チーム名、3位決定戦設定（デモ用に一部確定しているもの）は架空のものです。正式運用ではスプレッドシートの内容に差し替えてください。
