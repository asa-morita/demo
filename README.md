# 体育祭 2026｜4チーム総当たり・リアルタイム結果表示

4チーム・6競技の体育祭を、Cloudflare Workers と Google スプレッドシートで管理する閲覧用サイトです。
各競技は **1回総当たり：3節、各節2試合、計6試合**。各チームは3試合を行います。
従来の8チーム勝ち抜き式（QF/SF/FINAL/THIRD）は使用しません。

## 画面と開催枠

画面下部のナビゲーションは **予定 → 総合順位 → 対戦表** の3タブです。速報・全結果は独立タブとして表示しません。

- 大会全体の開催枠：12:30〜18:00（競技ごとの時刻は各シートで指定）
- 競技：フットサル／バレーボール／バスケットボール／ドッチボール／綱引き／借人競争
- 「予定」に4チーム全員の名前と共通の6対戦カード、競技予定を掲載します。
- 「総合順位」では4チームの確定ポイント・順位を表示します。
- 「対戦表」は **5行×5列の総当たりマトリクス表**です。先頭行・先頭列には4チーム名、交点には縦のチームから見た「勝／敗／未開始／試合中／要確認」を表示します。左上と同一チームの交点には斜線を引きます。スマートフォンでも横スクロール不要で5列が収まります。
- マトリクス表の下には従来どおり競技別の暫定順位・勝利数・敗北数・試合数を表示します。
- 勝者と試合の進行状態は対戦表で確認できます。各試合のスコアは**公開しません**。

### 対戦表（5×5）の見方

列見出し・行見出しには「チーム」シートの4チームを同じ順番で表示します。
交点は行側のチームの結果で、**勝利なら「勝」、敗北なら「敗」** と表示します。対戦カード1試合につき、行と列を入れ替えた対称位置にも相手側から見た結果を表示します。
まだ確定していない試合では「未開始」「試合中」、データが矛盾した試合では「要確認」と表示します。
左上のセルおよび同一チームが交差する4セルは斜線で埋め、対戦なしを示します。
スコア表示は行わず、各セルの下段には第何節の試合かを表示します。

## 総当たりの日程

チームの順番は「チーム」シートの**上から4行**で決まります。次の例では A・B・C・D の順です。

| 節 | match_id | 対戦 |
|---|---|---|
| 第1節 | R1M1 | A vs D |
| 第1節 | R1M2 | B vs C |
| 第2節 | R2M1 | A vs C |
| 第2節 | R2M2 | D vs B |
| 第3節 | R3M1 | A vs B |
| 第3節 | R3M2 | C vs D |

各カードは1度だけ行い、全6試合の **status が「終了」かつ勝者が有効** になってから競技の順位を確定します。
未開始・試合中の試合では勝利数は加算しません。

### 順位の決め方

1. **勝利数の多いチームを上位**にします。
2. 2チームが同じ勝利数の場合は、両者の**直接対決の勝者**を上位にします。
3. 3チーム以上が同じ勝利数の場合は、試合スコアによる得失点差を取得しないため**同順位**とします（全試合終了後も同様）。

同順位が生じた場合は競技内で同一順位のポイントをそれぞれ獲得します（例：3チーム同率1位なら全員30点で、次は4位）。
これはスコア非公開・勝者のみ入力という現行ルールを保つための方式です。

### 総合順位のポイント（固定）

| 競技別順位 | ポイント |
|---|---:|
| 1位 | 30 |
| 2位 | 20 |
| 3位 | 10 |
| 4位 | 0 |

全6試合が有効に終了した競技のポイントを一括計上し、未完了競技ではポイントを加算しません。
総合順位が同点の場合は、優勝回数 → 準優勝回数 → 3位回数で比較し、なお同じなら同順位です。
配点はプログラム内で固定しています。旧「配点」シートは参照しません。

## Google スプレッドシートの構成

テンプレートは `templates/` の **チーム.csv／競技.csv／試合.csv** にあります。
1つのスプレッドシートに3タブを作成して、CSVのヘッダー・データを貼り付けてください。

### 「チーム」タブ

| id | name |
|---|---|
| A | Aチーム |
| B | Bチーム |
| C | Cチーム |
| D | Dチーム |

**重複しない4チームちょうど**必要です。順番を変えた場合は「試合」タブの対戦カードも合わせて更新してください。
旧8チームのままだとAPIはデータを受け付けません。

### 「競技」タブ

| 列 | 項目 | 説明 |
|---|---|---|
| A | id | 競技ID |
| B | name | 競技名 |
| C | third_place | 旧形式互換のため列のみ保持、総当たりでは無視 |
| D | order | 表示順 |
| E | start_time | 開始時刻、例：13:00（未定なら空欄） |
| F | end_time | 終了時刻（未定なら空欄） |
| G | venue | 会場（任意） |

### 「試合」タブ

| 列 | 項目 | 説明 |
|---|---|---|
| A | sport_id | 競技ID |
| B | match_id | R1M1、R1M2、R2M1、R2M2、R3M1、R3M2 |
| C | team_a | 対戦チームA側のID |
| D | team_b | 対戦チームB側のID |
| E | score_a | 任意・非表示（従来互換） |
| F | score_b | 任意・非表示（従来互換） |
| G | status | 未開始／試合中／終了 |
| H | winner_id | 終了時の勝者のチームID |
| I | court | コート（任意） |
| J | scheduled_at | 開始予定（任意） |

試合を終えたら **status を「終了」、winner_id を実際の勝者のID** に更新してください。
点数欄は空欄で構いません。旧形式の点数が入力されていて勝者IDが空欄の場合のみ、自動判定を試みます。引き分けには対応していません。
`match_id` の重複、期待された対戦カードとの不一致、無効な勝者IDは「要確認」となり、競技の確定を保留します。

**旧スプレッドシートを使っていた場合は「チーム」および「試合」タブの内容を新テンプレートで置き換えてください。**
QF/SF/FINAL/THIRDの旧行を残しても新日程には反映されません。

## 結果入力画面（/admin）

サイトの `/admin` で管理者ログイン後、競技別に6試合の状態（未開始・試合中・終了）と勝者を選び、試合単位で保存できます。終了時は勝者の選択が必須です。結果を変更するとGoogleスプレッドシート「試合」タブのG列（status）・H列（winner_id）が更新され、公開画面にも数秒以内に反映されます。「試合中」や「未開始」に戻すと勝者はクリアされます。

**管理者画面を有効にするためには**、Cloudflare WorkerのSettings → Variables and Secretsで次の値を設定してください。

| Secret | 用途 |
|---|---|
| `ADMIN_PASSWORD` | 管理者ログイン用パスワード（長い文字列を推奨） |
| `ADMIN_SESSION_SECRET` | 署名付きセッション用の、別のランダムな文字列（32文字以上を推奨） |
| `SHEETS_SPREADSHEET_ID` | GoogleシートのID |
| `SHEETS_CLIENT_EMAIL` | Googleサービスアカウント |
| `SHEETS_PRIVATE_KEY` | Googleサービスアカウントの秘密鍵 |

サービスアカウントに対象シートの**編集者**権限を与えてください。`SHEETS_API_KEY` だけでは保存できません。これらの認証情報をGitHubにコミットしないでください。

管理者セッションは署名付きHttpOnly Cookieで管理され、8時間で期限切れになります。変更の競合は再読み込みを求めて保護します。ログインの試行回数制限はWorkerインスタンス単位なので、本番ではCloudflare側でも `/api/admin/login` のレート制限を推奨します。

## Cloudflare Workers への公開

1. GitHub `asa-morita/demo` を Cloudflare Workers & Pages に接続します。
2. デプロイコマンドは `npx wrangler deploy`、ビルド時のテストは `npm test` を推奨します。
3. Google未接続の場合は `public/demo-data.json` からデモを表示します。
4. 運営のGoogleシートと接続するときは以下の環境変数を Worker に設定します。

| 環境変数 | 内容 |
|---|---|
| `SHEETS_SPREADSHEET_ID` | GoogleスプレッドシートID |
| `SHEETS_CLIENT_EMAIL` | サービスアカウントのメールアドレス |
| `SHEETS_PRIVATE_KEY` | サービスアカウント秘密鍵。**Cloudflare Secretsに格納** |
| `SHEETS_API_KEY` | 公開シートを使用する場合の代替APIキー（任意） |

Google CloudでGoogle Sheets APIを有効にし、管理画面を使用する場合はサービスアカウントに対象シートの編集権限を付与します。
秘密鍵はGitHubにコミットしないでください。

ページは約5秒ごとに `/api/results` を取得し、WorkerはSheetsの3タブを `values.batchGet` でまとめて読み込み、5秒キャッシュを利用します。
Cloudflareキャッシュはデータセンター単位のため、世界中で完全に同期しているわけではありません。
