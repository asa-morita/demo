# 体育祭 2026 | リアルタイム・トーナメント

8チーム×複数競技の試合速報、トーナメント、総合順位、全結果を閲覧できるCloudflare Workersサイトです。

UIは **学サポ時間割（gakusapo）** の固定黒ヘッダー、黄色のアクセント、丸型ボタン、下部タブを参考にしています。コードやブランド名は複製していません。

## 画面と仕様

- **速報**：全競技の試合中／終了試合、全体の進捗
- **対戦表**：競技別。スマホは準々決勝・準決勝・決勝（設定次第で3位決定戦）を切り替え、PCでは全ラウンドを同時表示
- **総合順位**：各競技が完全に終了した時だけ順位別ポイントを加算。配点はスプレッドシートで変更可
- **全結果**：競技とラウンド別に全試合を表示
- データを**5秒間隔**で再取得。取得に失敗した場合は直近の表示を維持し、通信エラーを表示
- 勝敗確定時には、次ラウンドの対戦相手を計算。先行試合の結果を訂正した際の対戦相手の不一致も検知
- 編集権限はGoogleスプレッドシートに委ね、公開Webサイトには管理者ログインやAPI秘密鍵を置かない

初期状態は**デモデータ**であり、実際の体育祭試合結果ではありません。Google Sheetsを設定するとデモから切り替わります。

## Google スプレッドシートの構成

**1つのファイル**に、以下の4つのタブを**完全一致**の名前で用意します。1行目は見出し、2行目以降がデータです。テンプレートCSVは `templates/` にあります。

### チーム

| A: id | B: name |
|---|---|
| A | Aチーム |
| B | Bチーム |
| ... | ... |
| H | Hチーム |

8件ちょうど。チームIDは全競技で共有し、名前は自由に変更できます。

### 競技

| A: id | B: name | C: third_place | D: order |
|---|---|---|---|
| volley | バレーボール | 未定 | 1 |
| dodge | ドッジボール | 未定 | 2 |
| basket | バスケットボール | 未定 | 3 |

`third_place` は **あり/true/1** =3位決定戦を実施、**なし/false/0** =実施しない、**未定/空欄** =方針未決定とします。未定の競技はポイントを確定しません。行の追加で競技数を増やせます。

### 試合

| 列 | 名前 | 内容 |
|---|---|---|
| A | sport_id | 競技ID（例：volley） |
| B | match_id | QF1〜QF4 / SF1〜SF2 / FINAL / THIRD |
| C | team_a | 対戦チームID。準決勝以降は後述 |
| D | team_b | 対戦チームID |
| E | score_a | Aの得点（未入力は空欄） |
| F | score_b | Bの得点（未入力は空欄） |
| G | status | 未開始 / 試合中 / 終了 |
| H | winner_id | 勝者ID。引き分け等の場合は必須。通常は得点から自動判定 |
| I | court | コート・場所（任意） |
| J | scheduled_at | 試合予定時刻（任意） |

1競技につき**準々決勝4試合＋準決勝2試合＋決勝1試合＝7試合**。3位決定戦ありの場合に `THIRD` 行を追加してください。

- QF1勝者×QF2勝者 = SF1、QF3勝者×QF4勝者 = SF2。
- SF1勝者×SF2勝者 = FINAL。3位決定戦ありならSF1敗者×SF2敗者 = THIRD。
- SF1以降は、Web表示側で対戦相手を自動算出。**スコア確定前にC/D列に実際の対戦チームIDを記録**する運用を推奨します。先行試合を訂正した場合、C/D列と新しい勝者が一致しなければ後続試合を「要確認」として無効化します。
- G列「終了」かつH列に有効な勝者ID、またはE/F列に異なる数値得点がある場合に勝者確定。両者同点のときはH列を明示してください。
- シートの編集履歴はGoogleスプレッドシート側が管理します。

### 配点

| A: rank | B: points |
|---|---|
| 1 | 10 |
| 2 | 7 |
| 3 | 5 |
| 4 | 3 |
| 5 | 1 |

**上記はデモ用の仮配点**です。正式な体育祭の配点に置き換えてください。3位決定戦がない場合は準決勝敗者2チームを同率3位に、5〜8位決定戦がない場合は準々決勝敗者4チームを同率5位に扱います。競技の3位決定戦ルールが未定の間は、その競技の総合ポイントをまだ加算しません。

総合順位はポイント降順→優勝回数→準優勝回数→3位回数で比較。完全に同じなら同順位です。大会独自の配点や同点判定があれば調整できます。

## Cloudflare公開方法（Workers Static Assets）

1. Cloudflare Dashboardから **Workers & Pages → Create → Worker** で作成、GitHub `asa-morita/demo` を接続（または `npm run deploy` でCLI公開）。
2. Workers Buildsのビルドコマンドを `npm test`（省略も可）、デプロイコマンドを `npx wrangler deploy` に設定。
3. 初回デプロイは設定不要。URLを開くと明示的なデモデータを表示します。
4. Google Sheetsを接続する場合は以下の環境変数をCloudflareのWorker設定に登録します。

| 変数 | 種別 | 内容 |
|---|---|---|
| `SHEETS_SPREADSHEET_ID` | 文字列 | URLの `/spreadsheets/d/...` のID |
| `SHEETS_CLIENT_EMAIL` | シークレット推奨 | Googleサービスアカウントのメール |
| `SHEETS_PRIVATE_KEY` | **シークレット必須** | サービスアカウントの秘密鍵（PEM、改行含む） |
| `SHEETS_API_KEY` | 代替・シークレット | 公開閲覧可能シートに限ってAPIキー方式を使用 |

**推奨はプライベートなシート＋サービスアカウント**です。Google Cloud ConsoleでGoogle Sheets APIを有効にし、サービスアカウントを作成して、当該シートをサービスアカウントのメールアドレスに**閲覧者**として共有します。APIキーだけを使う場合はスプレッドシートを一般公開の閲覧可能状態にする必要があり、意図せぬ情報公開に注意してください。

※このリポジトリに秘密鍵、APIキー、スプレッドシートへの書き込み権限をコミットしないでください。

## 技術・更新の注意

- Cloudflare WorkerはGoogle Sheets APIの `values.batchGet` で4つのタブを**まとめて1回で取得**します。GoogleへのアクセスはWorkerだけが行います。
- Worker Cache APIの5秒キャッシュと同一インスタンス内の同時取得まとめ処理を使用。**Cache APIはデータセンターごとのキャッシュで、全世界で厳密に1回/5秒ではありません**。大規模配信にはDurable Objects等による取得集約を追加してください。
- 参加者全員が5秒ごとにWorkerへアクセスするため、**Cloudflare Workersのリクエスト割り当て**にも注意してください。例：100人×12回/分×4時間＝288,000回。無料枠を超え得ます。必要に応じて有料プランまたはポーリング間隔を10〜15秒へ変更してください。
- Google Sheets APIの1プロジェクト当たりの読み取り割り当てと、同一サービスアカウントの読み取り割り当ての双方が適用されます。
- ネット接続・Google API停止時は、直近の成功データを可能な範囲で表示し、通信エラー／古いデータを明示します。
- Googleシートは唯一の正本です。このサイトに書き込む機能はありません。
